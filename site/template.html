An investment-research agent that has to prove its numbers

The model writes the code; the contract decides whether the number counts. quantifact treats agentic analysis as a compiler problem — a question is clarified into a typed plan with a knowledge date, every task compiles in parallel into one pandas function, and every stage after that is deterministic machinery rather than an agent deciding what to do next. Everything on this page was measured from a live run of the repository.

Independent open-source implementation of the investment-research agent architecture Bridgewater Associates described publicly at INTERRUPT26 (the “Pat, the Pocket Analyst” talk). Clean-room, synthetic data, no Bridgewater code, data or trademarks; not affiliated with or endorsed by Bridgewater.

Numbers below come from this repository (quantifact, pandas, no API key required: uv add quantifact && qf ask). Where the original talk's figures are quoted they are labelled as such — the two are never mixed.

The mechanism

Two agents, one intermediate representation

The chat agent never sees code; the coding agent never sees the user. What crosses between them is a plan detailed enough to compile: every dataframe, its columns, units and semantic roles, its row grain, its row order, its invariants — and the knowledge date the whole analysis is bound to.

What makes it a compiler and not a to-do list

  • Task == a function type signature. Name, description, index columns, output columns with dtype and unit, row grain, invariants.
  • Plan == a natural-language Python project. Dependencies are declared and closed before a single token is spent on code.
  • Compile errors exist. Cycles, unknown upstreams, columns nobody produces, conflicting units and unbound series are rejected at plan time.

Where determinism actually comes from

  • Conventions, enforced statically: one function, fixed signature, no IO, no randomness, no clock, explicit sort.
  • Contracts, checked on the result: declared columns, dtypes, non-null ratios, ranges, uniqueness.
  • Architecture, not diligence: the loop is ordinary Python, so a model cannot skip a check it finds inconvenient.
The part the talk did not need to specify

Point-in-time, by construction

A firm with fifty years of data infrastructure already has this. Everyone else has to build it, and it is the difference between research and fiction: an analysis of the past is worth something only if it could have been run in the past.

Three enforcement points, hardest last to argue with

  • The loader is bound. The harness hands generated code a load_series already closed over the knowledge date; static analysis rejects any keyword argument to it. Late data is not filtered out — it is never handed over.
  • Dated outputs are checked. Any column with role observation_date must not post-date the knowledge date, which catches code that invents dates instead of reading them.
  • The cache key carries it. The same code at a different as_of is a different question and gets a different entry.

Universes are read as of the date too, so a name delisted in 2008 belongs to a 2007 universe and not to a 2026 one. Asking to include an event that had not begun raises LookAheadError at plan time.

Execution

What the caching harness buys

The talk's headline comparison is against Claude Code, which is not reproducible here. What is reproducible — and is the actual mechanism — is the same plan and the same generated code executed with the harness's content-addressed cache switched on versus off.

Why the shapes match even though the scales don't

This replication compiles pandas from a structured spec instead of calling a model, so its absolute times are milliseconds, not minutes. The ratios survive because they come from the same two mechanisms the talk describes: the edit re-executes one task instead of the whole plan, and codegen wall time is set by the slowest single task rather than by their number. The codegen view measures that second property with a fixed simulated per-task latency, which is labelled as a simulation everywhere it appears.

Swapping in a real model

What happens when the code emitter is an LLM

The deterministic compiler is an oracle, not a product. So the same plan was handed to a real model through an OpenAI-compatible endpoint, and every task it wrote was graded: does it pass each layer, and does it produce the same values as the oracle?

      Data binding
      
      The inspection pass, which is where search accuracy comes from
      
      
      Recall finds candidates; inspection decides. Frequency, unit,
        coverage and whether the values match a prior are checked explicitly, and every
        accept or reject is written into the trace so a background agent can audit it.
      
    
      
    
      
    
      The store deliberately contains traps: a CPI index where a
      rate is wanted, the same rate quoted in basis points under the same unit
      label, and a quarterly twin of a monthly series. Only the value-prior check
      separates the second one from the series you actually want. Series named
      PAT.* are outputs of earlier runs that landed back in the store — they
      are searchable like anything else, and lose ties to vendor data on purpose, so an
      analysis never silently chains itself to a previous one.

      Traps worth avoiding
      
        
        
          
      • A plan that is a to-do list. Without schemas there is no
            parallel codegen, no cache identity and nothing to validate against.
        • 
          
      • Letting the model run its own code. You lose caching,
            traces, containment and reproducibility in one move.
        • 
          
      • LLM-as-judge as the primary eval. A reproducible agent
            deserves assertions; soft scores send hill-climbing into noise.
        • 
          
      • Permission checks in the prompt. Un-entitled tools should
            not be loaded, and the index should filter before ranking.
        • 
          
      • Outputs that do not land in the store. Without write-back
            there is no compounding between people and agents.
        • 
        
      
      
      
      
      
        
      What this replication does not include
      
        
        
          
      • The unstructured vault. Millions of subscribed documents
            have no stand-in here; the search layer covers time series only.
        • 
          
      • Fifty years of investment context. The domain context is a
            handful of lessons, not a firm's methodology.
        • 
          
      • A model in the loop by default. The LLM codegen, semantic
            validator and debugger backends exist and are wired in, but the default path
            is the deterministic reference compiler so everything on this page is
            reproducible without an API key.
        • 
          
      • Real market data. The store is synthetic and seeded; the
            numbers describe machinery, not markets.
